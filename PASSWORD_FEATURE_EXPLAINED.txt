HOW THE "CHANGE / RESET PASSWORD" FEATURE WAS BUILT
====================================================

This file explains, step by step and in simple words, what was added so that
residents and guards can change their password, and the secretary can reset it.


WHAT THE FEATURE DOES
---------------------

1. A resident or guard can change their OWN password.
   - They must type their current password first (this proves it is really them).
   - Then they type the new password two times.
   - After the change, they stay signed in on the phone/computer they are using,
     but they are signed out on all their other devices.

2. The secretary can RESET the password of a resident or guard.
   - This is for people who forgot their password.
   - The secretary does not need the old password.
   - The secretary can only do this for people in THEIR OWN building.
   - After the reset, that person is signed out everywhere. The secretary
     then tells them the new password (in person or by phone).

3. Secretaries cannot use either of these.
   - A secretary's password is managed by the developer (you).
   - To change a secretary's password, run this in the project folder:
         python manage.py changepassword <secretary_username>


STEP 1 - Let the server "sign people out"
-----------------------------------------
File: griha/settings.py

Login in this project uses JWT tokens (from the "simplejwt" library).
When someone logs in, they get two tokens:
   - an "access" token  (works for 15 minutes)
   - a "refresh" token  (works for 7 days, used to get new access tokens)

Normally the server cannot cancel a token once it is given out. So if a
password is changed, the old login would keep working for up to 7 days.

To fix that, we turned on simplejwt's "token blacklist" add-on by adding this
line to INSTALLED_APPS:

    'rest_framework_simplejwt.token_blacklist',

Then we ran:

    python manage.py migrate

This created two new tables:
   - one that remembers every refresh token that was given out
   - one that lists refresh tokens that are cancelled ("blacklisted")

A cancelled refresh token can no longer be used to stay logged in.


STEP 2 - A helper to sign someone out everywhere
------------------------------------------------
File: accounts/utils.py   ->   function sign_out_everywhere(user)

It finds every refresh token that belongs to the user and puts each one on
the blacklist. Result: every device of that user is logged out.

Small note: the short "access" token on a device can still work for up to
15 minutes. After that the device tries to refresh, gets refused, and the
person has to sign in again with the new password.


STEP 3 - Checking the form data (serializers)
---------------------------------------------
File: accounts/serializers.py

We added three things:

a) check_new_password(password, confirm, user)
   A shared check used by both features:
   - the two new passwords must be the same
   - the password must pass Django's built-in rules:
       * at least 8 characters
       * not a very common password (like "password123")
       * not only numbers
       * not too similar to the username

b) ChangePasswordSerializer   (for residents and guards)
   Fields: current_password, new_password, confirm_password
   - checks the current password is correct
   - checks the new password is different from the current one
   - runs check_new_password

c) ResetPasswordSerializer    (for the secretary)
   Fields: new_password, confirm_password
   - runs check_new_password (no old password needed)


STEP 4 - The API endpoints (views)
----------------------------------
File: accounts/views.py

a) ChangePasswordView
   - Only residents and guards are allowed (secretaries get "403 Forbidden").
   - Checks the data with ChangePasswordSerializer.
   - Saves the new password with user.set_password(...) - Django stores it
     safely as a hash, never as plain text.
   - Calls sign_out_everywhere(user).
   - Creates NEW tokens and sends them back, so the current device stays
     signed in.

b) ResetMemberPasswordView
   - Only the secretary is allowed.
   - Looks for the person by id, but ONLY if:
       * they are a resident or a guard, AND
       * they live in this secretary's building.
     If not found -> "404 Not found". (So a secretary can't touch another
     building's people, or another secretary.)
   - Checks the data with ResetPasswordSerializer.
   - Saves the new password and calls sign_out_everywhere(member).


STEP 5 - The web addresses (URLs)
---------------------------------
File: accounts/urls.py

    POST /accounts/password/change/
         body: { "current_password": "...", "new_password": "...", "confirm_password": "..." }
         answer: { "detail": "...", "access": "...", "refresh": "..." }

    POST /accounts/members/<id>/password/reset/
         body: { "new_password": "...", "confirm_password": "..." }
         answer: { "detail": "..." }

If something is wrong, the answer is "400" with a message for the field that
is wrong, for example:
    { "current_password": ["Your current password is not correct."] }


STEP 6 - Automatic tests
------------------------
File: accounts/tests.py   (11 tests)

They check, among other things:
   - residents and guards can change their own password
   - a wrong current password is refused
   - weak, common, mismatched or unchanged passwords are refused
   - changing the password signs out the other devices,
     but the device that made the change stays signed in
   - secretaries cannot use "change password"
   - the secretary can reset a resident's and a guard's password
   - a reset signs that person out
   - a secretary cannot reset someone from another building, or a secretary
   - residents and guards cannot reset anyone

Run all tests with:

    python manage.py test

(All 41 tests in the project pass.)


STEP 7 - The screens (frontend)
-------------------------------

a) components/PasswordFields.jsx  (shared pieces)
   - "New password" + "Type it again" boxes, with a Show/Hide button.
   - A quick check before sending (at least 8 characters, not only numbers,
     both boxes the same). The server still does the full check.
   - suggestPassword(): makes a random password like "hT7k-Q9mx-W3pa".
     It leaves out letters that look alike (0/O, 1/l/I) so it is easy to
     read out over the phone.

b) Account page (app/account/page.jsx)  - for residents and guards
   - There is a "Password" section with a "Reset password" button.
   - The button opens a side panel asking for the current password and the
     new password twice.
   - On success, the new tokens are saved in the browser, so the person
     stays signed in here.
   - A secretary sees a note instead: "Your password is managed by the
     administrator."

c) People page (app/secretary/people/page.jsx)  - for the secretary
   - Every resident and guard row has a "Reset password" button.
   - It opens a side panel with the new password boxes and a
     "Suggest a password" link (the suggestion is shown so the secretary
     can read it out).
   - After the reset, a message reminds the secretary to give the person
     their new password and username.

d) lib/api.js
   - Added the two new addresses: API.changePassword and API.resetPassword(id).


THINGS TO KNOW
--------------
- People who were already logged in BEFORE this feature was added were given
  tokens the server never recorded, so a reset can't sign those old sessions
  out. They expire by themselves within 7 days. Every login from now on is
  recorded, so this only matters once.
- There is no "forgot password by email" yet. If someone forgets their
  password, they ask their secretary to reset it.
